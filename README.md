# NBA Analytics Dashboard

An interactive analytics dashboard for the 2024-25 NBA season built with DuckDB and Streamlit. The application allows users to explore player game logs, compare players head-to-head, track team monthly trends, view statistical leaderboards, and run custom SQL queries — all powered by DuckDB's columnar query engine.

## Project Overview

This project fetches 2024-25 NBA player box score data using the `nba_api` library, stores it in a local DuckDB database, and serves it through a multi-page Streamlit dashboard. The database contains 1,314 games, 577 players, and 34,928 player-game records spanning the full regular season (October 22, 2024 to April 2025) and playoffs (through June 22, 2025).

## Data Pipeline

The `data/` folder and `nba.duckdb` are already included in this repository. You do not need to run the fetch notebook or the database setup script to use the application. Simply clone the repository and run `streamlit run app.py` as described in [Running the Application](#running-the-application).

The steps below are provided for reference if you want to understand or reproduce the full pipeline from scratch.

The data pipeline has two steps: fetching raw data and loading it into the database.

### Step 1 — Fetch NBA Data

Open and run `fetch_data.ipynb` in Jupyter:

```bash
jupyter notebook fetch_data.ipynb
```

Run all five cells in order:

1. **Cell 1** — Loads libraries and creates the `data/` directory.
2. **Cell 2** — Fetches all 2024-25 game records for Regular Season and Playoffs using `LeagueGameLog`.
3. **Cell 3** — Deduplicates to one row per game, parses home and away teams, and saves `data/games.csv`.
4. **Cell 4** — Fetches individual player box scores for every game using `BoxScoreTraditionalV3`. This step makes one API call per game with randomized delays to avoid rate limiting. **This step takes approximately 20 to 40 minutes to complete.**
5. **Cell 5** — Selects the relevant stat columns, merges game metadata, and saves `data/player_boxscores.csv` and `data/players.csv`.

After running the notebook, the `data/` directory will contain three CSV files:
- `games.csv` — 1,314 rows
- `players.csv` — 577 rows
- `player_boxscores.csv` — 34,928 rows

## Database Setup

Once the CSV files exist in `data/`, load them into DuckDB by running:

```bash
python setup_db.py
```

This script will:
- Create `nba.duckdb` in the project directory
- Drop and recreate the three tables (safe to re-run)
- Load all three CSV files using DuckDB's native `read_csv_auto()`
- Print row counts to confirm successful loading

Expected output:

```
Creating database at: /path/to/project/nba.duckdb
Loading Games...
Loading Players...
Loading PlayerBoxScores...

Done!
   Games:           1,314
   Players:           577
   PlayerBoxScores: 34,928
```

## Running the Application

1. Clone the repository and navigate into the project folder:

```bash
git clone https://github.com/Dlyang8/DSCI_551.git
cd DSCI_551
```

2. Activate your virtual environment if you have one set up:

```bash
source venv/bin/activate        # On Windows: venv\Scripts\activate
```

3. Open your terminal (Mac/Linux) or Command Prompt / PowerShell (Windows), make sure you are inside the project folder where `app.py` is located, and run:

```bash
streamlit run app.py
```

4. Streamlit will start a local server and automatically open the dashboard in your default browser. If it does not open automatically, copy the URL printed in the terminal and paste it into your browser. It will look like this:

```
Local URL: http://localhost:8501
```

The app connects to `nba.duckdb` in read-only mode. No internet connection is required once the database file is present in the project folder. Make sure you are running the command from the same directory that contains both `app.py` and `nba.duckdb`, otherwise the app will not find the database.

## Reproducing Results

To fully reproduce this project from scratch:

1. Clone the repository and set up the virtual environment as described above.
2. Install all dependencies.
3. Run `fetch_data.ipynb` end-to-end to regenerate the CSV files. Note that API results may differ slightly from the included dataset if the NBA Stats API updates historical records.
4. Run `setup_db.py` to rebuild `nba.duckdb` from the CSV files.
5. Run `streamlit run app.py` to launch the dashboard.

If the `data/` CSVs and `nba.duckdb` are already included in the repository, steps 3 and 4 can be skipped. Run `setup_db.py` only if you want to rebuild the database from the CSV files.

## Database Schema

### Games

| Column | Type | Description |
|---|---|---|
| GAME_ID | VARCHAR (PK) | Unique game identifier |
| GAME_DATE | DATE | Date the game was played |
| HOME_TEAM | VARCHAR | Home team abbreviation |
| AWAY_TEAM | VARCHAR | Away team abbreviation |

### Players

| Column | Type | Description |
|---|---|---|
| PLAYER_ID | INTEGER (PK) | Unique player identifier |
| PLAYER_NAME | VARCHAR | Full player name |
| TEAM | VARCHAR | Most recent team abbreviation |

| Column | Type | Description |
|---|---|---|
| GAME_ID | VARCHAR | Foreign key to Games |
| PLAYER_ID | INTEGER | Foreign key to Players |
| PLAYER_NAME | VARCHAR | Full player name |
| TEAM_ABBREVIATION | VARCHAR | Team the player represented in this game |
| MIN | VARCHAR | Minutes played |
| PTS | DOUBLE | Points |
| REB | DOUBLE | Rebounds |
| AST | DOUBLE | Assists |
| STL | DOUBLE | Steals |
| BLK | DOUBLE | Blocks |
| TOV | DOUBLE | Turnovers |
| FGM | DOUBLE | Field goals made |
| FGA | DOUBLE | Field goals attempted |
| FG_PCT | DOUBLE | Field goal percentage (0 to 1) |
| FG3M | DOUBLE | Three-pointers made |
| FG3A | DOUBLE | Three-pointers attempted |

| SEASON_TYPE | VARCHAR | "Regular Season" or "Playoffs" |

## Application Pages

### Player Game Log
Displays a full game-by-game log for any selected player with a configurable rolling average overlay for points and assists. Uses DuckDB window functions (`AVG() OVER ... ROWS BETWEEN`) computed over sorted game dates.

### Player Comparison
Compares season averages across all major statistical categories for any two players. Filterable by season type. Uses vectorized `GROUP BY` aggregation over columnar data.

### Team Monthly Trends
Shows a selected team's average performance for a chosen stat broken down by calendar month. Uses `STRFTIME` date extraction and `GROUP BY` in a single columnar scan.

### Leaderboard
Ranks the top 25 players by any selected statistic with a configurable minimum games played threshold. Uses `ORDER BY` and `LIMIT` on aggregated results computed in a parallel pass over the relevant columns.

### Custom Query
A free-form SQL editor for running read-only queries directly against the DuckDB engine. Includes five pre-built example queries and an optional query plan viewer via `EXPLAIN`. Only `SELECT`, `WITH`, and `EXPLAIN` statements are permitted.
